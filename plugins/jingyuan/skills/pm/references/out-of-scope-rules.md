# PM Out-of-Scope 规则

本文件在 `$jingyuan:pm` 做范围裁剪、记录本期不做或处理反复出现的拒绝需求时读取。

## 什么时候写入 PRD

以下内容写入 `docs/PRD/prd.md` 的“本期不做”：

- 明确不是 MVP 必需。
- 做了会拖慢第一版验证。
- 用户确认以后再做。
- 与当前产品定位不一致。

## 什么时候写入 docs/out-of-scope

以下内容写入 `docs/out-of-scope/<topic>.md`：

- 同类需求反复出现，容易被后续技能重新建议。
- 用户明确拒绝，并给出长期有效原因。
- 涉及安全、合规、成本或产品定位的硬边界。
- 某个方案被评估后决定不采用，未来读者需要知道原因。

## 文件格式

```markdown
# <不做事项>

## 结论

本项目当前不做 <事项>。

## 原因

- <原因 1>
- <原因 2>

## 影响

- 后续 PRD、设计、开发计划不得把该事项重新纳入范围，除非用户明确推翻本记录。

## 重新考虑条件

- <触发条件>

## 来源

- <用户确认 / PRD 版本 / 反馈记录>
```

## 使用规则

- `dev-plan` 不得规划 out-of-scope 内容。
- `dev-builder` 发现开发计划包含 out-of-scope 内容时，停止并提示回到 `$jingyuan:pm` 或 `$jingyuan:sync`。
- `evolution` 发现重复 out-of-scope 反馈时，优先更新知识库，不反复生成相同建议。
