### 36.1 关于原型链

1. 对象属性 / 方法的查找机制

   - 查找顺序：
     - 先查找对象自身（`obj.xxx`）
     - 如果没有，会沿着对象的原型链向上查找（即`obj.__proto__`）
     - 直到找到`Object.prototype`(根原型)，如果仍未找到则抛出错误

2. 构造函数与原型对象

   - 构造函数（如`Person`）默认自带一个`prototype`属性，该属性是一个对象

   - 原型对象（`Person.prototype`）会成为所有通过`new Person()`创建的实例的原型

     ```javascript
     function Person(){
         this.name = "景元"
     }
     Person.prototype.age = 18; //所有 Person 实例共享此属性
     ```

3. 原型链继承

   - 继承关系通过`__proto__`链接，例如：

     ```javascript
     Object.setPrototypeOf(Son.prototype, Person.prototype);
     ```

   - `Son`的实例会先查找自身属性，在查找`Son.prototype`，最后查找`Person.prototype`

   - 多层继承

     ```javascript
     Object.setPrototypeOf(Window.prototype, WindowProperties.prototype);
     Object.setPrototypeOf(WindowProperties.prototype, EventTarget.prototype);
     ```

   - `window`实例的原型链为：`Window -> Window.prototype -> WindowProperties.prototype -> EventTarget.prototype -> Object.prototype`

4. 原型链的查找示例

   - 示例1：

     ```javascript
     Person.prototype = {
         age:18,
         chi: function(){
             console.log("我爱吃东西")
         }
     };
     
     var p = new Person();
     
     // 每一个对象都会有该属性, __proto__ 会指向该对象的原型对象
     console.log(p.__proto__);
     
     
     function Son(){}
     Son.prototype.chi = function(){
         console.log("儿子爱吃东西");
     }
     
     function Person(){}
     
     Person.prototype.he = function(){
         console.log("人爱喝东西")
     }
     // 把a的原型对象设置为b    Object.setPrototypeOf(a, b)
     Object.setPrototypeOf(Son.prototype, Person.prototype);
     
     var son = new Son();
     son.he(); // 1.对象自身没有该方法, 2. Son.prototype也没有该方法, 3. 原型对象的原型对象上有he
     ```

5. `__proto__`和`prototype`的区别

   | 属性        | 说明                                                   |
   | ----------- | ------------------------------------------------------ |
   | `__proto__` | 对象的私有属性，指向该对象的原型对象                   |
   | `prototype` | 函数的属性，作为其构造函数的实例的原型对象（仅函数有） |

   

### 36.2 属性描述符

1. 属性描述符即控制对象属性的行为特征，共分为两种类型：

   - 数据描述符：管理属性值

   - 访问器描述符：通过`getter/setter`控制访问

   - `Object.defineProperty()`允许精确的控制对象属性的行为

     ```javascript
     Object.defineProperty(对象, "属性名", 描述符对象);
     // 参数的说明
     对象 -- 要在其上定义属性的对象
     属性名 -- 要定义或修改的属性的名称（字符串）
     描述符对象 -- 描述属性行为的对象，通过描述符对象可以精确控制属性是否可写、可枚举、可配置；通过闭包+访问器实现创建真正的私有变量；可以在setter中添加验证逻辑进行数据验证；可以实现拦截属性访问
     ```

     

   描述符属性详解

   | 属性名       | 类型     | 默认值   | 适用描述符类型 | 作用                                                         |
   | ------------ | -------- | -------- | -------------- | ------------------------------------------------------------ |
   | value        | any      | undefind | 数据描述符     | 属性值                                                       |
   | writable     | boolean  | false    | 数据描述符     | 是否允许修改属性值                                           |
   | get          | function | undefind | 访问器描述符   | 访问属性时执行的函数，返回值作为属性值                       |
   | set          | function | undefind | 访问器描述符   | 设置属性时执行的函数，接收新值作为参数                       |
   | configurable | boolean  | false    | 两者皆可       | 是否允许：<br />修改描述符<br />删除属性<br />改变类型（数据/访问器） |
   | enumerable   | boolean  | false    | 两者皆可       | 是否在以下操作中可见：<br />`for……in`<br />`Object.keys()`<br />`JSON.stringify()` |

   

2. 访问器描述符（`getter/setter`），通过函数控制属性的读取和赋值操作

   ```javascript
   // 重定义document.cookie属性
   Object.defineProperty(document, "cookie", {
       get(){
           return "哈哈"; // 读取cookie时返回固定字符串
       },
       set(val){
           console.log("你给该属性设置了一个值", val); // 设置时仅打印日志
       }
   });
   
   console.log(document.cookie); //输出：“哈哈”
   document.cookie = "<REDACTED_SECRET>"; //打印：你给该属性设置了一个值 马大哈
   ```

   - 当读取`document.cookie`时，触发`get()`方法并返回固定的字符串；

   - 当设置`document.cookie`时，触发`set()`方法设置属性值（这里仅做了日志打印，并没有真的存储）；

3. 数据描述符（`value/writable`），直接定义属性值以及其可写性

   ```javascript
   var obj = {};
   Object.defineProperty(obj, "ehtan", {
       value:"马大哈", // 初始值
       writable:false, // 禁止修改
   });
   
   console.log(obj.ethan); //输出：马大哈
   obj.ethan = "新的值";   // 修改失败，严格模式下会报错
   console.log(obj.ethan); //输出：马大哈
   ```

   - `writable:false`使属性不可修改（类似常量）
   - 修改尝试在非严格模式下静默失败，严格模式抛出错误

4. 闭包配合访问器（数据封装），实现真正的私有变量控制

   ```javascript
   var obj = {};
   (function(){
       var _internal = "初始值"; // 闭包保护的私有变量
       
       Object.defineProperty(obj, "ethan", {
           get(){
               console.log("获取值");
               return _internal;
           },
           set(val){
               if(val.length > 5){// 添加校验逻辑
                   console.log("设置值", val);
                   _internal = val;
               }
           }
       });
   })();
   
   console.log(obj.ethan); // 初始值
   obj.ethan = "短"; // 校验失败
   obj.ehtan = "足够长的值"; // 成功设置
   ```

   - 通过创建闭包环境，保护`_internal`变量
   - `setter`中添加了长度校验的逻辑
   - 外部无法直接访问私有变量

5. 配置权限（`configurable`），控制属性描述符的修改权限

   ```javascript
   var obj = {};
   Object.defineProperty(obj, "lockProp", {
       value:"不可配置",
       configurable:false, //锁定配置
   });
   
   // 尝试重新配置（报错）：TypeError：Cannot redefine property
   Object.defineProperty(obj, "lockProp", {
       value:"新值",
       configurable:true // 尝试解锁
   });
   
   // 尝试删除（失败）
   delete obj.lockProp; // false
   ```

   - `configurable:false`禁止：
     - 删除属性
     - 修改描述符（除`writable`从`true`改为`false`）
     - 切换描述符类型（属性 <-> 访问器）

6. 可见性控制（`enumerable`），控制属性在枚举操作中的可见性

   ```javascript
   var obj = {
       name:"公开属性"
   };
   
   Object.defineProperty(obj, "hiddenProp", {
       value:"隐藏属性",
       enumerable:fasle // 不可枚举
   });
   
   //枚举测试
   console.log(Object.keys(obj));//只输出["name"]
   console.log(JSON.stringify(obj));//输出{"name":"公开属性"}
   
   // 直接访问仍然可见
   console.log(obj.hiddenProp); // 输出：隐藏属性
   
   //获取所有属性名（含不可枚举）
   console.log(Object.getOwnPropertyNames(obj)); // ["name","hiddenProp"]
   ```

   枚举操作影响：

   - `for .... in`循环
   - `Object.keys()`
   - `JSON.stringify()`
   - `Object.assign()`

7. 描述符查看`API`

   ```javascript
   var obj = {
       name:"示例"
   };
   
   Object.defineProperty(obj, "age", {
       value:18,
       enumerable:fasle
   });
   // 查看单个属性属性描述符
   console.log(Object.getOwnPropertyDescriptor(obj, "age"));
   /*
   {
   value:18,
   writable:false, // 默认值
   enumerable:false,
   configurable:false // 默认值
   }
   */
   
   // 查看所有属性描述符
   console.log(Object.getOwnPropertyDescriptors(obj));
   /*
   {
   name:{value: "示例", writable: true, enumerable: true, configurable: true},
   age: {value: 18, writable: false, enumerable: false, configurable: false}
   }
   */
   ```

8. 原型链属性定义，在构造函数原型上定义属性

   ```javascript
   function Myclass(){}
   // 在原型上定义只读属性
   Object.defineProperty(MyClass.prototype, "VERSION", {
       value:"1.0",
       writable:false
   });
   
   var instance = new MyClass();
   console.log(instance.VERSION); //1.0
   instance.VERSION = "2.0"; //修改无效（原型链属性）
   ```

9. 知识体系图

   ```tex
   属性描述符体系
   ├─ 核心功能
   │  ├─ 数据描述符：value + writable
   │  └─ 访问器描述符：get + set
   ├─ 通用控制
   │  ├─ configurable（配置锁）
   │  └─ enumerable（可见性）
   ├─ 相关API
   │  ├─ defineProperty/defineProperties
   │  ├─ getOwnPropertyDescriptor/Descriptors
   │  └─ getOwnPropertyNames（含不可枚举）
   └─ 应用模式
      ├─ 只读常量（writable:false）
      ├─ 私有变量（闭包+访问器）
      ├─ 属性隐藏（enumerable:false）
      └─ 属性锁定（configurable:false）
   ```


### 36.3  脱环境框架`vm2`

`vm2`是`Node.js`中的一个模块，它提供了一种在沙箱环境中执行`javascript`代码的方式。沙箱环境允许你在一个相对安全的环境中运行不信任的代码，防止恶意代码对系统的损害。`vm2`的主要作用是创建和管理这样的沙箱环境。

什么是沙箱？沙箱是一种安全机制，用于在计算机系统中隔离和限制程序或代码的执行环境，以防止对系统的不良影响。有点类似于`python`的虚拟环境，如果虚拟环境奔溃了，不会影响到真实环境。

简而言之，`vm`提供了一个干净的独立环境供我们进行测试，帮助我们打造一个真实的浏览器环境。在`Node.js`中，我们可以通过引入`vm`模块来创建一个`沙箱`。但其实这个`vm`模块的隔离功能并不完善，还有很多缺陷。因此，`Node.js`后续升级了`vm`，也就是现在的`vm2`沙箱，`vm2`引用了`vm`模块的功能，并在此基础上做了一些优化。

**安装命令**

```javascript
npm install vm2
```

示例：我们只需要实例化之后调用`run`方法即可运行一段脚本。

```javascript
const {VM, VMScript} = require("vm2");
const script = new VMScript("let a = 2; a");
let vm = new VM();
console.log(vm.run(script));
```

**框架搭建**：搭建框架可以分为3个部分

- 需要加载的环境，一般存放在`evn`文件夹中；
- 需要补环境的代码；
- `vm2`加载全部代码到沙箱环境中

**框架结构：**

```te

├─ env文件夹:存放环境相关的代码
│  ├─ BOM文件夹：
│  │  ├─ config.js文件：
│  │  ├─ document.js文件：
│  ├─ DOM文件夹：
│  │  ├─ config.js文件：
│  └─ main.js文件：
├─ JSCode：存放需要操作的JS代码
│  ├─ main.js文件：
│  └─ 在网站抠出来需要执行的JS代码.js文件：

```

> `DOM`或者`BOM`文件夹是用来存放相关环境的`JS`代码文件。而文件夹下对应的`config.js`文件是用来配置读取对应文件夹下面的`JS`代码文件的。文件夹中有多少关于`JS`的代码文件，就需要在`config.js`中配置多少信息。

**结合深度代理和浅层代理，让DeepSeek优化出的自吐环境脚本**

```javascript
// 代理缓存防止循环引用
const proxyCache = new WeakMap();

// 值格式化函数（增强可读性）
function formatValue(value) {
    if (value === null) return 'null';
    if (value === undefined) return 'undefined';
    const type = typeof value;
    switch (type) {
        case 'function':
            return `函数[${value.name || '匿名函数'}]`;
        case 'object':
            if (Array.isArray(value)) {
                return `数组[长度=${value.length}]`;
            }
            if (value instanceof Node) {
                return `DOM节点[${value.nodeName}]`;
            }
            if (value instanceof Element) {
                return `元素[${value.tagName}]`;
            }
            return '对象';
        case 'string':
            return value.length > 50 ? `字符串[长度=${value.length}]` : `"${value}"`;
        default:
            return String(value);
    }
}

// 核心代理创建器
function createTracingProxy(target, name = '全局对象') {
    // 非对象直接返回
    if (target === null || typeof target !== 'object') return target;
    // 检查缓存
    if (proxyCache.has(target)) return proxyCache.get(target);
    // 创建代理
    const proxy = new Proxy(target, {
        get(obj, prop) {
            const value = Reflect.get(obj, prop);
            const fullPath = name ? `${name}.${String(prop)}` : String(prop);
            // 格式化输出
            console.log(
                `从对象[${name}] --> 获取了属性[${String(prop)}] --> ` + 
                `属性[${String(prop)}]的值 == ${formatValue(value)}`
            );
            // 递归代理
            return createTracingProxy(value, fullPath);
        },
        set(obj, prop, value) {
            console.log(
                `向对象[${name}] --> 设置属性[${String(prop)}] --> ` + 
                `新的值 == ${formatValue(value)}`
            );
            return Reflect.set(obj, prop, value);
        },
        apply(func, thisArg, args) {
            // 格式化参数
            const formattedArgs = args.map(arg => formatValue(arg)).join(', ');
            console.log(
                `调用了函数[${name}] --> ` + 
                `参数 == [${formattedArgs}]`
            );
            try {
                const result = Reflect.apply(func, thisArg, args);
                console.log(
                    `函数[${name}] --> ` + 
                    `返回值 == ${formatValue(result)}`
                );
                // 代理返回值
                return createTracingProxy(result, `${name}(返回值)`);
            } catch (error) {
                console.error(
                    `函数[${name}] --> ` + 
                    `调用出错 == ${error.message}`
                );
                throw error;
            }
        }
    });
    // 加入缓存
    proxyCache.set(target, proxy);
    return proxy;
}
// ======== 环境初始化 ========
const envProxies = {};
// 代理核心环境对象
const coreObjects = [
    'window', 'document', 'location', 
    'navigator', 'history', 'screen'
];
coreObjects.forEach(key => {
    if (key in globalThis) {
        envProxies[key] = createTracingProxy(globalThis[key], key);
    } else {
        // 创建缺失对象的兜底
        envProxies[key] = createTracingProxy({}, key);
        console.warn(`创建了缺失的全局对象: ${key}`);
    }
});
// 特殊补全常见API
if (!envProxies.document.querySelector) {
    envProxies.document.querySelector = createTracingProxy(
        function selector() { return null; }, 
        'document.querySelector'
    );
}
// 覆盖全局对象
Object.entries(envProxies).forEach(([key, proxy]) => {
    try {
        globalThis[key] = proxy;
    } catch (err) {
        console.error(`覆盖全局对象失败: ${key}`, err);
    }
});
// 自检日志
console.log('自吐环境初始化完成，开始追踪操作...');
```

> 当程序自吐环境后，如何确定是否需要补环境，需要通过联调方式定位代码的位置，对比浏览器上的代码是否一致，吐出的环境是undefined，浏览器环境也是undefined，就不需要补。如果不是，就需要按浏览器显示的内容补环境。
