#### 22.2.1	MD5

`MD5`是一种非常常见的摘要算法，又称为哈希算法或者离散算法。是将任意长度的数据提取特征值后转换为固定长度的唯一字符串，通常用16进制字符串表示。其特点是不可逆性、唯一性和确定性。所以，`MD5`是国内非常多的互联网公司选择使用的摘要算法之一。一般用来存储密码、检验文件一致性（相同的数据计算出来的hash值是相同的）。这种标准的摘要算法是公用的。

MD5（Message Digest Algorithm 5）

- `c4ca4238a0b923820dcc509a6f75849b`
- 特征类型 16进制，长度32为，
- `0-9`和`a-f`组合而成
- 可以猜测是`md5`加密

**通过`Python`实现`MD5`加密：**

```python
# 在数学上，摘要算法的计算逻辑就是hash，所谓的hash就是 hash(数据)函数返回的是数字，哈希的特点是不可逆的。
from hashlib import md5

# 1.创建MD5对象 
obj= md5()
# 2.通过utf-8对内容进行编码
name = "alex".encode("utf-8")
# 3.对编码内容进行计算
obj.update(name)
# 4.导出32位MD5值
bs = obj.hexdigest()
print(bs) #534b44a19bf18d20b71ecc4eb77c572f

# 简要写法
import hashlib
data = "hello".encode("utf-8")
md5_hash = hashlib.md5(data).hexdigest()
print(md5_hash)#5d41402abc4b2a76b9719d911017c592
```

> 需要注意：创建的MD5对象`obj`是一次性的，不能反复使用。另外，MD5有个默认的问题是可能被撞库，因为MD5存在的年头实在太长了，很多内容都被计算过，难免会遇到相同的内容。可以在创建md5对象的时候，添加字符串进行干扰，俗称“撒盐”。可以起到对抗撞库问题，例如：`obj= md5(b"my name is ethan")`

而其他的摘要算法如：`sha1`、`sha256`、`sha512`，它们几个就相当于超级版的`MD5`，代码逻辑是一样的，就是把`md5()`替换成`she1()`即可。对比图表如下：

| 算法    | 输出长度 | 安全性     | 速度 | 使用场景         |
| ------- | -------- | ---------- | ---- | ---------------- |
| MD5     | 32位     | 不安全     | 快   | 非敏感校验       |
| SHA-1   | 40位     | 不安全     | 中   | 旧系统兼容       |
| SHA-256 | 64位     | 安全       | 较慢 | 密码存储、区块链 |
| SHA-512 | 128位    | 更高安全性 | 最慢 | 高安全需求场景   |
| SHA-3   | 可变     | 抗量子计算 | 慢   | 未来安全系统     |

不论是`sha1`、`sha256`还是`md5`都属于摘要算法，都是在计算`hash`值，只是散列的程度不同而已，这种算法有一个特性，它们是散列，不是加密。而且，由于`hash`算法是不可逆的，所以不存在解密的逻辑。

**通过`JavaScript`实现`MD5`加密：**

安装对应模块

```javascript
npm install crypto-js
```

使用案例

```javascript
// 引入crypto-js加密模块
var CryptoJS = require("crypto-js");

// 创建加密函数
function MD5Test(){
    var text = "1"
    return CryptoJS.MD5(text);
}

// 输出加密结果
console.log(MD5Test());
// 此时得到的结果是
{
  words: [ -993377736, -1598479486, 231493786, 1869972635 ],
  sigBytes: 16
}
// 这被称作“标准幻数”，生成幻数后还需要使用toString()方法，转换成字符串
```

生成幻数后还需要使用`toString()`方法，转换成字符串，以下是完整的`md5`加密逻辑

```javascript
var CryptoJS = require("crypto-js");

function MD5Test(){
    var text = "1";
    return CryptoJS.MD5(text).toString();
}
console.log(MD5Test()) // c4ca4238a0b923820dcc509a6f75849b
```

> 数字1经过`md5`计算后，就是`c4ca`开头的字符串，以后可以通过这个特征验证是否为`md5`加密

#### 22.2.2 UrlEncode

在访问一个`URL`的时候总能看到这样的一种`URL`，在浏览器中可以看到中文，可一旦复制出来，或者在抓包工具中看到，都是这种%E5%91%A的东西

```python
https://www.sogou.com/web?query=%E5%91%A8%E6%9D%B0%E4%BC%A6&_asf=www.sogou.com
```

`%E5%91%A8%E6%` 其实是我们在访问`URL`的时候，浏览器会自动进行`URL encode`操作。会对我们请求的`URL`进行编码。那么，一个完整的`url`有哪些部分组成呢？例如：`scheme://host:port/dir/file?p1=v1&p2=v2#anchor`

- `scheme` 协议：如`https`、`http`等
- `host` 主机`IP`地址或者域名：`IP`地址就是通过`DNS`服务器转换成域名
- `port` 端口号： `https`默认端口`443`，`http`默认`80`，所以默认的可以不写
- `dir` 文件夹： `IP`+`端口`=`应用程序`，所以就是某一个应用程序下的某一个文件夹
- `file` 文件：文件夹下面的文件
- `p1=v1` 参数：多个参数之间用`&`分开 `key=value`服务器通过`key`获取`value`
- `#anchor` 锚：进入到页面后定位到什么位置

如果参数中出现一些特殊字符，比如`=`，想给服务器传递`a=b=c`这样的参数，必然会让整个`URL`产生歧义。所以为了避免参数导致整个`URL`含义的改变，把`URL`中的参数部分转换成字节，每一个字节再转化成`2个16`进制的数字，前面补`%`这个操作就是`URL encode`

**在`Python`中的实现方式：**

```python
# 导包
from urllib.parse import quote,unquote

# quote 把字符串编码
text = "临兵斗者皆阵列前行"
encoded = quote(text, safe="") # safe参数指定不编码的字符（默认包含/等）
print(encoded)

# unquote 把经过编码的字符串解码，还原
encode = "%E4%B8%B4%E5%85%B5%E6%96%97%E8%80%85%EF%BC%8C%E7%9A%86%E9%98%B5%E5%88%97%E5%89%8D%E8%A1%8C"
text = unquote(encode)
print(text)

# 编码查询参数字典:将参数value中的中文编码
from urllib.parse import urlencode

params = {"name":"小明", "age":20}
encoded_params = urlencode(params)
print(encoded_params) # name=%E5%B0%8F%E6%98%8E&age=20
```

#### 22.2.3 **Base64**

HTTP协议传输的本质是二进制字节流，但某些场景（如JSON、URL参数）仅支持文本数据。若需传输二进制内容（如图片、加密后的密文），直接发送原始字节可能导致协议解析错误或数据损坏。

> **Base64算法**的作用是将**二进制数据（字节）**转换为**由64个ASCII字符组成的字符串**，确保其在文本环境中的安全传输。编码后的字符串可通过解码还原为原始字节。
>
> 例如，加密后的数据（字节）通过Base64编码为字符串，嵌入HTTP请求体中；服务器接收后解码为字节再解密。Base64本身不提供加密功能，仅解决数据表示问题。
>
> `base64` 由`A-Z`、`a-z`、`0-9`、以及`/`和`+`组成，一共64个符号。
>
> 编码过程每3字节转为4字符，数据体积增加约33%，但保证了跨系统的兼容性。

**记住：base64的本质就是字节！**

**在`Python`中实现方法：**

```python
# 普通字符串编码成base64字符串
import base64

s = "临兵斗者皆阵列前行" # 字符串
bs = s.encode("utf-8") # 先把字符串编码成UTF-8字节
print(bs) #b'/xe4/xb8/xb4/xe5/x85/xb5/xe6/x96/x97/xe8/x80/x85/xe7/x9a/x86/xe9/x98/xb5/xe5/x88/x97/xe5/x89/x8d/xe8/xa1/x8c'
b64_str = base64.b64encode(bs) # 再把字节编码成Base64字节
print(b64_str) # b'5Li05YW15paX6ICF55qG6Zi15YiX5YmN6KGM'

b64_str = b64_str.decode() # 再把Base64字节解码成字ASCII字符串
print(b64_str) # 5Li05YW15paX6ICF55qG6Zi15YiX5YmN6KGM


# base64字符串解码成普通字符串
b64_str = "5Li05YW15paX6ICF55qG6Zi15YiX5YmN6KGM"  # base64字符串
b64_bs = base64.b64decode(b64_str) # 把base64字符串解码成base64字节
print(b64_bs) #b'/xe4/xb8/xb4/xe5/x85/xb5/xe6/x96/x97/xe8/x80/x85/xe7/x9a/x86/xe9/x98/xb5/xe5/x88/x97/xe5/x89/x8d/xe8/xa1/x8c'
s = b64_ba.decode() # 把base64字节解码成字符串
print(s) # 临兵斗者皆阵列前行
```

**请注意：**

由于标准的`Base64`编码后可能出现字符`+`和`/`，但是这两个字符在`url`中是不能当作参数传递的，所以就出现了`Base64url`，下面是它们的区别：

1. `Base64`编码后出现的`+`和`/`在`Base64URL`会分别替换为`-`和`_`
2. `Base64`编码中末尾出现的`=`符号用于补位，这个字符和`queryString`中的`key=value`键值对会发生冲突，所以在`Base64URL`中`=`符号会被省略，去掉`=`后怎么解码呢？因为`Base64`是把3个字节变为4个字节，所以，`Base64`编码的长度永远是`4`的倍数，因此，需要加上`=`把`Base64`字符串的长度变为4的倍数，就可以正常解码了。

我们的应对方案：在处理`base64`的时候，如果遇到了没有`+`和`/`的情况，可以采用下面的方案来替换掉`+`和`/`。
`b64 = base64.b64decode(mi, b"-_")`

#### 22.2.4 `HMAC`算法

全称散列消息认证码、密钥相关的哈希运算消息认证码。它要求通信双方共享密钥`key`、约定算法、对报文进行`hash`运算，形成固定长度的认证码。通信双方通过认证码的校验来确定报文的合法性。

**JavaScript实现**

```javascript
// 引用 crypto-js 加密模块
var CryptoJS = require("crypto-js");

function HMACEncrypt(){
    var text = "my name is ethan";
    var key = "secret"; // 密钥文件
    return CryptoJS.HmacMD5(text, key).toString();
    // 或者还可以进行sha系列计算，例如
    // CryptoJS.HmacSHA256(text, key).toString();
}

console.log(HMACEncrypt()) // 30b74f8c9aac51250333c6f60be62340
```

**python实现**

```python
import hmac

def hmac_encrypt():
    text = "my name is ethan".encode()
    key = "18岁"encode()
    hmac_ = hmac.new(key, text, digestmod="MD5")
    print(hmac_.hexdigest())
    
hmac_encrypt()  #e7f69467d3401333606ec068e13b66b6
```







### 22.3 对称加密

数据经过处理，变成一堆人类无法解读的内容，在进行数据传输后，对方把无法解读的内容再还原回可解读的状态，这一过程就是数据的 **加密** 与 **解密** 过程。

加密的过程一般是在服务器完成并且看不到的。解密的过程是在客户端完成的。

所谓对称加密，是指在加密和解密的时候，使用的都是同一个密钥。所以，只要有这个密钥就可以解密。常见的对称加密有：`AES`、`DES`、`3DES`

| 算法     | 密钥长度           | 块大小 | 特点                                                         | 安全性         |
| -------- | ------------------ | ------ | ------------------------------------------------------------ | -------------- |
| **AES**  | 128/192/256 位     | 128 位 | 速度快、安全性高，广泛用于政府和商业领域，支持多种模式（CBC、GCM） | 高（推荐）     |
| **DES**  | 56 位（64 位存储） | 64 位  | 已过时，易被暴力破解，仅用于遗留系统                         | 不安全         |
| **3DES** | 112/168 位         | 64 位  | DES 的三次迭代，速度慢于 AES，兼容旧系统                     | 中（逐步淘汰） |

所以，此部分内容针对 AES 重点讲解与掌握。

#### 22.3.1  AES（重点）

安装模块

```python
pip install pycryptodome
```

使用`python`实现加密的方法：

生成随机密钥必须是`16`、`24` 或者 `32` 字节的长度，对应的就是`AES-128`、`AES-192`、`AES-256`。生成随机的初始向量必须是16字节的。

所谓的填充与拆解，是指加密和解密过程是分组处理的，如果分组不均的时候，需要对数据进行填充，填充`pad`，取消填充`unpad`

常见的加密模式有两种：

- mode=AES.MODE_ECB 该模式下不需要给 iv 偏移量，该模式是进行分组加密然后拼接在一起

- mode=AES.MODE_CBC 该模式下需要给 iv 偏移量，数据加密之前会增加偏移量，iv 必须是16字节


填充的逻辑：

- `AES`是一种分组密码，块大小为16字节。加密时，输入数据必须是块大小的整数倍（即16字节的倍数）
- 如果明文长度不足块大小（例如14字节），直接调用`cipher.encrypt(plaintext)`会抛出异常，因为加密函数无法处理不完整的块
- `pad` 的作用就是将明文扩展到块大小的整数倍，确保假面过程正常进行
- `unpad` 去除填充，需要在完成解密后，将填充的内容去除，才可以还原成正常的明文

**加密逻辑**：填充明文 --> 加密 --> 输出密文

```python
# 导入必要的包
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad # 自动填充补位和自动拆解补位
from Crypto.Random import get_random_bytes # 生成随机密钥和初始向量

# 生成随机密钥(AES-256)
key = get_random_bytes(32) # 32字节=256位
# 生成随机初始向量 (IV 16字节)
iv = get_random_bytes(16)
# 明文数据，编码成字节
plaintext = "临兵斗者皆阵列前行".encode("utf-8")
# 创建 AES-CBC 加密器
cipher = AES.new(key, AES.MODE_CBC, iv)
# 加密（自动填充）
ciphertext = cipher.encrypt(pad(plaintext, AES.block_size))


# 得到的结果需要转换成字符串，通常使用base64()，也可以使用hex()
# base64
print(base64.b64encode(key).decode()) # 密钥
print(base64.b64encode(iv).decode()) # 偏移量
print(base64.b64encode(ciphertext).decode()) # 密文

# hex()
print("密钥：", key.hex())
#密钥： bfafc7bd89494bb89a391e7bd4d9b173b1352eec952172205b849a1467109f10
print("IV：", iv.hex())
#IV： 7b771cdea7251bb0b4fd442bfcdef16e
print("密文：", ciphertext.hex())
#密文： 5e78712088ea7e4fc25d31e81df4061d522a66d5863eaee3c1f0cfab0d4c8fdf
```

**解密逻辑：**解密密文 --> 去除填充 --> 还原明文

```python
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad
# 将十六进制字符串转换成字节，也可以将字节转换成十六进制字符串
# hex() 字节转16进制字符串
# unhexlify() 16进制字符串转字节
from binascii import unhexlify

# 解密，需要拿到密文、密钥、偏移量，16进制字符串要转成字节才能使用
key = unhexlify("bfafc7bd89494bb89a391e7bd4d9b173b1352eec952172205b849a1467109f10")
iv = unhexlify("7b771cdea7251bb0b4fd442bfcdef16e")
ciphertext = unhexlify("5e78712088ea7e4fc25d31e81df4061d522a66d5863eaee3c1f0cfab0d4c8fdf")
# 创建解密器
cipher = AES.new(key, AES.MODE_CBC, iv)
# 解密并去除填充
decrypted_data = unpad(cipher.decrypt(ciphertext), AES.block_size)
# 转回字符串
decrypted_text = decrypted_data.decode("utf-8")
print("解密结果：", decrypted_text)
# 解密结果： 临兵斗者皆阵列前行
```

**总结：**

- **加密过程**：
  - 创建加密器：`aes = AES.new(key=key, iv=iv, mode=AES.MODE_CBC)`
  - 对数据填充：`plaintext_bytes = pad(plaintext.encode('uft-8'), 16)`
  - 对数据加密：`ciphertext_bytes = aes.encrypt(plaintext_bytes)`
  - 对密文做`base64`编码：`ciphertext_b64 = base64.b64encode(ciphertext_bytes).decode()`
- **解密过程**：
  - 创建解密器：`aes = AES.new(key=key, iv=iv, mode=AES.MODE_CBC)`
  - 对数据做`base64`解码：`ciphertext_bytes = base64.b64decode(ciphertext)`
  - 数据解密：`plaintext_bytes = aes.decrypt(cipher_bytes)`
  - 去除填充：`plaintext = unpad(plaintext_bytes, 16)`

### 22.4 非对称加密

非对称加密，加密和解密的秘钥不是同一个秘钥。服务器端生成一对密钥，一个公钥，一个私钥。公钥发送给客户端，客户端用公钥对数据加密，再发送给服务器，服务器使用私钥来对数据解密，由于私钥只存放在服务器这边，所以即使数据被截获了，也是无法进行解密的。相对于 AES 和 DES 的安全性有所提高。

常见的非对称加密算法见下表：

| 算法        | 密钥长度          | 特点                                         | 用途                 | 安全性                    |
| ----------- | ----------------- | -------------------------------------------- | -------------------- | ------------------------- |
| **RSA**     | 1024/2048/4096 位 | 通用性强，支持加密和签名，计算效率较低       | 加密小数据、密钥交换 | 高（推荐2048+）           |
| **ECC**     | 256/384 位        | 相同安全性下密钥更短，计算效率高，适合移动端 | 加密、签名、密钥交换 | 高（推荐曲线如secp256r1） |
| **DSA**     | 2048/3072 位      | 仅用于签名，不可加密，安全性依赖密钥长度     | 数字签名             | 中（逐步被ECC替代）       |
| **ElGamal** | 2048+ 位          | 支持加密和签名，但密文体积大（是明文的2倍）  | 加密、签名           | 高（较少使用）            |

**主要以 RSA 和 ECC 为例**

#### 22.4.2 ECC

密钥生成与共享

```python
from cryptography.hazmat.primitives.asymmetric import ec
from cryptography.hazmat.primitives.kdf.hkdf import HKDF

alice_public = alice_private.public_key()

bob_private = ec.generate_private_key(ec.SECP256R1())
bob_public = bob_private.public_key()

alice_shared = alice_private.exchange(ec.ECDH(), bob_public)

bob_shared = bob_private.exchange(ec.ECDH(), alice_public)

assert alice_shared == bob_shared

# 派生加密密钥（HKDF）
derived_key = HKDF(
    algorithm=hashes.SHA256(),
    length=32,
    salt=None,
    info=b"ECDH Key Derivation",
).derive(alice_shared)

print("共享派生密钥:", derived_key.hex())
```

KEY = "$shanghaidianqi$".encode('utf-8')  # 16 字节
IV = "2023050814260000".encode('utf-8')  # 16 字节


def aes_encrypt(plain_text):
    """
    对应 JS 中的 sr 函数：AES-CBC 加密
    :param plain_text: 要加密的明文（字典或字符串）
    :return: JSON 格式字符串，包含加密后的 data 字段
    """
    if isinstance(plain_text, dict):
        plain_text = json.dumps(plain_text, ensure_ascii=False)

    # 确保密钥和 IV 长度正确（AES-128 需要 16 字节）
    cipher = AES.new(KEY, AES.MODE_CBC, IV)
    # PKCS7 填充
    padded_data = pad(plain_text.encode('utf-8'), AES.block_size)
    # 加密
    encrypted = cipher.encrypt(padded_data)
    # Base64 编码
    encrypted_base64 = base64.b64encode(encrypted).decode('utf-8')

    return json.dumps({
        "data": encrypted_base64
    })


def aes_decrypt(cipher_text):
    """
    对应 JS 中的 mr 函数：AES-CBC 解密
    :param cipher_text: 加密后的 data 字段（Base64 字符串）
    :return: 解密后的明文字符串
    """
    try:
        # Base64 解码
        encrypted_bytes = base64.b64decode(cipher_text)
        # 创建解密器
        cipher = AES.new(KEY, AES.MODE_CBC, IV)
        # 解密
        decrypted_padded = cipher.decrypt(encrypted_bytes)
        # 移除 PKCS7 填充
        decrypted = unpad(decrypted_padded, AES.block_size)
        return decrypted.decode('utf-8')
    except Exception as e:
        raise ValueError(f"AES 解密失败: {e}")
