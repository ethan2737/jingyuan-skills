## 第25章：解决OB混淆

---

为什么要进行代码混淆？对于网页来说，其逻辑是依赖于JavaScript来实现的，JavaScript由如下特点：

- JavaScript运行于客户端，也就是它必须要在用户浏览器端加载并运行
- JavaScript代码是公开透明的，也就是说浏览器可以直接获取到正在运行的JavaScript源码

`OB混淆`是一种非常流行的`javascript`代码保护技术，旨在让代码变得极其难以阅读、立即和逆向工程，同时保持其功能不变。它的核心原理围绕几个关键技术实现：

这是一段源代码，随着混淆技术的使用会变的难以辨认：

```javascript
function verifyCode(code) {
    if (code === 12345) {
        showMessage("Access granted");
        return true;
    } else {
        showMessage("Invalid code");
        return false;
    }
}
```

### 25.1 字符串数组化与编码

- 提取：将代码中所有的字符串字面量（如`hello`、`debugger`、`function`）提取出来，放入一个巨大的数组中；
- 编码/混淆：这个数组本身通常会进行进一步的处理，比如：
  - 移位：在每个字符的`Unicode`码点加上或者减去一个固定值；
  - `Base64`编码：将字符串转换成`Base64`编码；
  - 自定义编码：使用更复杂的算法进行编码；
- 引用替换：在原始代码中，所有出现这些字符串的地方，都被替换成对这个数组特定索引的引用，例如（`_0x12ab34[0x10]`）

```javascript
// 字符串数组
const _0x5a8d = [
    'Access granted',  // 索引0
    'Invalid code',    // 索引1
    'showMessage'      // 索引2
];

function verifyCode(code) {
    if (code === 12345) {
        // 通过数组引用字符串
        window[_0x5a8d[2]](_0x5a8d[0]);
        return true;
    } else {
        window[_0x5a8d[2]](_0x5a8d[1]);
        return false;
    }
}
```

> 所有字符串消失，替换为`_0x5a8d[x]`引用，函数调用`showMessage()`变为`window[_0x5a8d[2]]()`

### 25.2 标识符混淆

- 将变量名、函数名（非全局`api`或关键函数）替换成无意义的、冗长的十六进制字符串（例如`_0x1a2b3c`、`_0xdeadbeef`）。这使得追踪变量流动变得异常困难。

```javascript

    if (_0x12cf8b === 12345) {  // code变为_0x12cf8b
        window[_0x5a8d[2]](_0x5a8d[0]);
        return true;
    } else {
        window[_0x5a8d[2]](_0x5a8d[1]);
        return false;
    }

```

> 函数名`verifyCode`变为`_0x10a3e3`，参数名`code`变为`_0x12cf8b`

### 25.3 控制流扁平化

- 这是`OB混淆`最具杀伤力的技术，将原本线性的、有层级结构的代码，如（`if/else`、`for`、`while`、`switch`、函数调用）打散成一系列的基本块。
- 调度器：引入一个中央调度器（通常是一个大的`while`循环和一个`switch`语句）。
- 状态变量：使用一个状态变量（通常也是一个混淆过的名字）来决定下一个要执行哪个基本块。
- 执行过程：代码不再是顺序执行或者跳转到明显的标签，而是不断地回到调度器。调度器根据当前状态变量的值，在`switch`语句中选择对应的`case`分支（即一个基本块）执行。该基本块执行完毕后，通常会修改状态变量的值，然后循环回调调度器，调度器在根据新的状态选择下一个基本块执行。

```javascript
const _0x5a8d = [ ... ]; // 同上

            // 初始状态

                    _0x38c21f = 1; // 跳转到case 1

```

> 线性代码被拆解为5个代码快`case 0-5`，通过`_0x38c21f` 状态变量控制执行流程，每次执行后都会回到`while + switch`调度中心

### 25.4 死代码注入与常量混淆

- 在扁平化的控制流中或函数中，插入大量永远不会被执行的代码块；
- 将数字常量（如`5`、`100`、`0x1F`）替换为等价的复杂表达式（例如`0x2 * 0x2 + 0x1`、`parseInt('64', 16)`、`~~3.14159`）。增加了阅读难度，但是最终的计算结果是相同的。

总结：最终通过混淆后的代码膨胀，可读性基本为零，无论是静态分析方法还是动态分析方法都变得非常困难，混淆的主要目的就是为了保护核心逻辑，例如：算法、加密密钥、`API`端点等等敏感信息不被轻易窃取或者复制。

当然，也不是说经过混淆的代码就无解了，通过浏览器开发者工具是可以逐步还原的，就是一个耐心和细心的过程，下面通过一个案例，看看如何解决`OB混淆`。
