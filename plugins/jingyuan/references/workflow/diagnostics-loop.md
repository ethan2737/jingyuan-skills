# Diagnostics Loop

Bug 和性能问题必须先建立反馈循环，再修改代码。

## Bug 修复

1. 定义症状：用户看到什么、系统输出什么、期望是什么。
2. 建立最小复现：测试、命令、接口请求、浏览器步骤或日志信号。
3. 列出 3-5 个可证伪假设。
4. 用最小实验逐个验证或排除假设。
5. 找到根因后做最小修复。
6. 把复现转成回归测试；无法自动化时写明 seam 限制和手动验证步骤。
7. 清理临时日志和插桩。

没有可重复失败信号，不进入修复阶段。

## 性能问题

1. 先建立 baseline：命令、数据量、环境、指标。
2. 找出瓶颈路径。
3. 一次只改一个变量。
4. 对比优化前后数据。
5. 如果优化引入复杂度，说明收益是否值得。

## 3-Strike Stop

满足任一条件时停止推进并上报：
- 连续 3 个假设失败。
- 修复触及超过 5 个文件且根因仍不清楚。
- 安全敏感路径无法验证。
- 性能测量不稳定且无法解释。

## Debug 清理

临时日志使用 `[DEBUG-xxxx]` 前缀。完成前用 PowerShell 搜索并清理：

```powershell
Get-ChildItem -Recurse -File | Select-String -Pattern '\[DEBUG-[A-Za-z0-9_-]+\]'
```
