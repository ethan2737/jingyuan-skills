# Vertical Slice 开发切片

JingYuan 的开发计划和实现应优先按端到端可验证切片组织，而不是水平分层。

## 定义

一个 vertical slice 是一条窄而完整的用户可验证路径，通常覆盖必要的 UI、API、数据、状态、错误处理和测试。

## 好切片

- 用户可演示或可验证。
- 有明确入口和结果。
- 覆盖真实集成路径。
- 完成后产品能力变多，而不只是多了一层基础代码。

## 坏切片

- “先建所有数据库表”
- “先写所有 API”
- “先做所有 UI”
- “先搭完整架构但没有可用功能”

## dev-plan 使用规则

- Phase 可以包含基础设施，但必须尽快接上第一个可验证行为。
- Phase 内 Task 优先写成用户行为：用户做什么，系统如何响应。
- 每个 Task 写清验收方式。

## dev-builder 使用规则

- 每个 Task 开始前确认它对应的用户可见行为。
- 每个 Task 完成后验证该行为，而不只验证文件存在或编译通过。
