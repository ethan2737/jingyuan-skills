# 变更记录模板

本模板用于记录 `docs/PRD.md` 的迭代、逆向建档和澄清历史。

---

## 文件命名

`docs/PRD-CHANGELOG.md`

---

## 模板格式

```markdown
# 变更记录

## [v1.2] - YYYY-MM-DD
### 新增
- <新增的功能或内容>

### 修改
- <修改的功能或内容>

### 删除
- <删除的功能或内容>

### 重构澄清
- <对旧逻辑、旧文档、旧实现的澄清或重写>

### 待确认关闭
- <哪个待确认项被确认了，最终结论是什么>

---

## [v1.1] - YYYY-MM-DD
### 修改
- <修改的功能或内容>

---

## [v1.0] - YYYY-MM-DD
### 新增
- 逆向建档，建立 PRD 基线
```

---

## 记录规则

- **版本号递增**：常规迭代默认 +0.1；重大重构或大版本重写可 +1.0。
- **日期自动填充**：使用当天日期，格式 `YYYY-MM-DD`。
- **分类记录**：使用 `新增`、`修改`、`删除`、`重构澄清`、`待确认关闭`。
- **逆向建档**：旧项目第一次补 PRD 时，允许在 `v1.0` 记录“逆向建档 / 基线建立”。
- **只记录实际变化**：没改的部分不写。
- **写清影响**：涉及核心流程、AI 能力、风险、边界条件时，写清改了什么以及影响点。
- **新增控件要写位置**：涉及 UI 变更时说明控件位置。
- **关闭待确认项要写结论**：不要只写“已确认”，要写确认后的最终规则。

## 完整示例

以下是「旧项目订单后台」的变更记录示例，供参考：

```markdown
# 变更记录

## [v1.2] - 2026-04-21
### 新增
- 新增「风险订单标记」需求，用于高风险退款单的人工复核

### 修改
- 将退款主流程补充为「运营发起 -> 财务审核 -> 系统执行退款 -> 审计记录入库」

### 重构澄清
- 根据退款页面代码行为与权限配置，澄清「高金额退款需要二次审核」是既有业务规则，不是新增设想

### 待确认关闭
- 关闭「批量退款审批是否已上线」待确认项，最终结论为：入口已存在，但后端未开放生产权限，当前不属于正式能力

---

## [v1.1] - 2026-04-18
### 修改
- 补充退款失败重试与审计日志要求
- 将成功指标从「提升效率」细化为「退款处理时长下降 30%」

### 删除
- 删除“自动通过所有低金额退款”的建议，避免引入资金风险

---

## [v1.0] - 2026-04-15
### 新增
- 逆向建档，基于 README、路由结构、退款页面和支付服务配置建立初始 PRD
```

## 写作要点

1. **动词开头**：
   - 新增、修改、删除、澄清、关闭待确认。

2. **描述具体**：
   - 写清“改了什么”、“改成什么样”、“影响哪里”。

3. **逆向类变更单独写**：
   - 若是把旧实现翻译成更清晰的需求，优先记到 `重构澄清`。

4. **待确认关闭必须写结果**：
   - 例如：关闭某条待确认项，确认最终规则是什么，而不是只写“已确认”。

5. **AI 能力变化单独成条**：
   - 新增、调整、移除 AI 能力时，不要和普通文案修改混在一起。
