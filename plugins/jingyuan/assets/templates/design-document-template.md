## 完整示例

以下是一个「AI 聊天助手桌面端」的 Design Brief 示例：

```markdown
## 产品概要
- 产品名称：Forge
- 产品类型：Desktop（Electron）
- 目标用户：开发者和技术用户，需要本地运行的 AI 助手
- 核心功能：聊天对话、Agent 管理、IM 桥接、定时任务

## 设计方向

### 审美立场
- **主审美方向**：冷静克制的开发者工具感，接近 Linear 的效率和 Raycast 的即时性
- **第一眼记忆点**：这是一个可信、快速、可控的本地 AI 工作台
- **设计原则**：信息优先于装饰；动效只服务状态理解；AI 自动化必须可暂停、可撤销、可追踪

### 安全选择 / 风险选择
| 类型 | 选择 | 理由 | 代价/边界 |
|------|------|------|-----------|
| 安全选择 | 深色专业工具界面 + 清晰侧边栏 | 开发者长时间使用，预期接近 IDE 和命令面板 | 不能为了酷牺牲可读性 |
| 风险选择 1 | 使用更有辨识度的标题字体和紧凑数据字体 | 避免通用管理后台感，强化产品性格 | 字体加载要克制，不能影响首屏 |
| 风险选择 2 | AI 工具调用用可折叠时间线呈现 | 让 Agent 行为透明，有高端交互感 | 默认折叠，避免挤占对话空间 |

### 情绪关键词
- **专业** — 面向开发者，不要花哨，信息传达清晰
- **沉稳** — 深色主题为主，长时间使用不疲劳
- **精致** — 细节考究但不过度设计，每个像素都有意义

### 参考产品
| 参考产品 | 喜欢的方面 | 不喜欢的方面 |
|---------|-----------|-------------|
| Linear | 信息密度高但不杂乱，动画流畅 | 无 |
| Arc Browser | 侧边栏设计，色彩运用 | 有些功能隐藏太深 |
| Raycast | 快捷键驱动，极简但功能强 | 有时信息太少 |

### 反面参考
- 企业后台风格：不要 Element UI / Ant Design 那种千篇一律的蓝白管理后台
- 花哨动画：不要 Framer 官网那种满屏动效

## 视觉规范

### 色彩方向
- **主题模式**：深色为主，支持浅色切换
- **色彩温度**：冷色
- **品牌主色方向**：深灰为底，靛蓝色作为品牌识别色
- **强调色方向**：珊瑚色用于警告/重要操作
- **品牌资产**：有自定义 mascot 图标

### 信息密度
- **密度方向**：偏紧凑
- **参考基准**：接近 Linear 的密度
- **理由**：产品有聊天、管理、设置等多个功能区，需要高效利用空间

### 排版方向
- **字体气质**：几何无衬线，干净利落
- **中文字体偏好**：系统默认即可
- **标题风格**：与正文差异适中，不需要太夸张

### 交互风格
- **动画程度**：适中——页面切换和列表操作有过渡，不需要花哨效果
- **过渡效果**：快速渐变为主，不要弹跳效果
- **整体节奏**：沉稳但不迟钝
- **微交互目标**：反馈和空间连续性，尤其是 AI 回复、工具调用、任务完成状态
- **禁用动效**：大面积视差、循环背景动画、弹跳式娱乐动效

### 设计令牌
- **颜色角色**：深灰背景、稍亮表面、白色主文本、灰色次文本、靛蓝品牌色、珊瑚色强调/警告
- **字体角色**：Display 用有辨识度的几何无衬线，Body 用高可读无衬线，Data/Code 用等宽字体
- **间距密度**：偏紧凑，基于 4pt/8pt 体系
- **圆角层级**：工具栏和输入框小圆角，浮层和卡片中圆角，避免全局大圆角
- **阴影/层级**：深色下以边框和表面亮度建立层级，少用重阴影
- **图标风格**：统一线性图标，避免 emoji 和混用图标库

### 可用性护栏
- **无障碍**：正文对比度满足长期阅读；焦点态清晰；关键操作支持键盘；尊重减少动态效果
- **响应式**：桌面端为主，窄屏保留聊天和任务查看，复杂管理功能允许降级
- **触控与输入**：按钮和图标有足够命中区域；表单错误内联展示；危险操作必须确认
- **性能预算**：首屏不依赖重图；字体最多加载必要字重；AI 流式输出不能造成布局跳动
- **安全错误处理**：错误提示不暴露 token、路径等敏感信息；任务失败提供重试和查看日志入口

### AI 体验
- **AI 生成呈现**：聊天回复流式出现，工具调用以可折叠时间线展示
- **透明度**：显示当前阶段、工具名、执行状态和失败原因
- **用户掌控**：支持停止、重试、复制、编辑上一轮输入
- **失败处理**：内联错误卡片，提供重试和展开技术详情两个层级

## 核心页面视觉备注

### 聊天界面
- **核心交互**：用户输入消息，AI 流式回复，支持工具调用展示
- **视觉方向**：偏 Claude/ChatGPT 的对话布局，AI 回复支持 Markdown 渲染
- **特殊要求**：工具调用要有可折叠的详情卡片，不能占满屏幕

### 管理面板（Skills/Agents/MCP）
- **核心交互**：三栏布局——分类导航 + 列表 + 编辑器
- **视觉方向**：偏 VS Code 的面板风格，左侧树形导航
- **特殊要求**：编辑器支持代码高亮和预览切换

### 侧边栏导航
- **核心交互**：图标导航 + Workspace 切换
- **视觉方向**：偏 Slack 的侧边栏，可折叠
- **特殊要求**：折叠后只显示图标

## 状态设计
- **空状态**：简短文案引导 + 操作按钮，不用插画
- **加载状态**：AI 回复用打字机光标，其他用骨架屏
- **错误状态**：内联错误提示，红色珊瑚色边框，不用弹窗
- **成功状态**：任务完成后轻量 toast + 状态回写，不打断用户
- **权限/安全状态**：敏感操作二次确认，错误详情默认折叠
```

## 写作要点

1. **情绪关键词**：最多 3 个，每个要解释在本产品中的具体含义
2. **参考产品**：必须标注"具体喜欢哪里"，不能只写产品名
3. **色彩方向**：写方向不写具体值（"蓝紫色调"而非"#6366F1"）
4. **信息密度**：必须附带参考基准（"像 XX 的密度"）
5. **核心页面备注**：只写有设计决策空间的页面，纯后端功能不写
6. **状态设计**：空、加载、错误三种状态都要有方向
7. **审美立场**：必须写主方向、记忆点、安全选择、风险选择，否则容易生成普通模板
8. **设计令牌**：必须写颜色、字体、间距、圆角、层级、图标的角色关系
9. **可用性护栏**：无障碍、响应式、触控/输入、性能预算、安全错误处理必须有最低要求
10. **高端交互**：微交互必须说明服务目标，禁止为了"炫"而动
11. **AI 体验**：涉及 AI/Agent/自动化时，必须写透明度、用户掌控和失败处理
12. **整体原则**：这份文档是给设计工具和 dev-builder 看的，要具体到能执行，但不要具体到像素级
